# SmesharikiMod

Управление игрой и миром. Minecraft 26.2, Java 25, Fabric (Loom). Id мода и пространство имён — `smesharikimod`, пакет `com.smeshariki.mod`. **Корень графа модов** (с 2026-11-13, решение пользователя: «одна общая зависимость»): в него влит бывший UiLib — общий интерфейс окон `com.smeshariki.ui`, от SmesharikiMod зависят все остальные моды, он же ставит их с GitHub; собирать его первым. Ничего, кроме Fabric API, ему не нужно. Бывший InstallerMod (переименован 2026-11-10, решение пользователя); в него перенесены версии мира и переключатель проверки аккаунтов из BuildMod. Карта проекта — `../CLAUDE.md`.

## Правила работы

- **После каждой правки:** собрать (`./gradlew jar --no-daemon -Dorg.gradle.jvmargs=-Xmx900m`) и положить `build/libs/smesharikimod-1.0.0.jar` (не `-sources`) в `~/.minecraft/mods/smesharikimod-1.0.0.jar` атомарно (`cp` во временный `.jar.tmp` и `mv -f`). Старый `installermod-*.jar` из mods убрать: иначе два мода с одним делом.
- Собирать **раньше** BuildMod и LevelMod: они компилируются против `../SmesharikiMod/build/libs/smesharikimod-1.0.0.jar`.
- Графического клиента у агента нет: UI и передачу файлов он проверить не может; сервер — `./gradlew runServer`.

## Что здесь

- `sync/`, `net/`, клиентские `SyncClient`, `SyncScreen`, `SyncSession` (бывший InstallerMod): сервер при входе игрока отдаёт манифест файлов из `mods/`, `resourcepacks/`, `shaderpacks/`, клиент спрашивает подтверждение и качает куски; имена файлов проверяются, пути нормализуются, SHA-256 сверяется. Раздаются только те моды, что загружены при старте (`onlyServeLoadedMods`). Режим **с подтверждением** — решение пользователя, автоматическую установку отвергли как небезопасную. Настройки — `config/smesharikimod.json` (прежний `installermod.json` переносится сам).
- **Установка с GitHub** (2026-11-12, по просьбе: «загрузка с гита, если это сам хост»; логика проверена на локальном сервере, `docs/level-sim` → `gitTest`; **в живой игре не проверено; с настоящим релизом на GitHub установка в пустую папку игры проверена (`realGit`)**). `sync/GitRelease` (без Minecraft): последний релиз репозитория `владелец/имя` (`gitRepo` в `config/smesharikimod.json`, `gitAutoCheck`, `gitApiBase`) содержит `manifest.json` (файлы: имя, `category` mod/resourcepack/shaderpack/world, размер, SHA-256, для мира `world`) и сами файлы; в план идёт то, чего нет или что отличается по сумме, мир — только если папки в `saves/` ещё нет. Ходить можно только по https на узлы GitHub (каждая переадресация проверяется), `http://localhost` — только если `gitApiBase` указывает туда (для проверок). `client/GitSession` (тот же интерфейс `SyncView` и тот же `SyncScreen`, что и раздача с хоста): загрузка в отдельном потоке, сверка суммы, заменяемый файл → `*.smesharikimod-old`, мир распаковывается во временную папку (защита от zip-slip и архива-бомбы) и ложится в `saves/`. `client/GitUpdate`: один раз за запуск на экране заголовка, только с подтверждением. Новая категория `SyncCategory.WORLD` (последняя в протоколе; сервер мир не раздаёт). Хост-раздача для гостя осталась как была. Репозиторий по умолчанию — `NoPasaRun/smeshariki-demo` (`SyncConfig.gitRepo`); пустое значение отключает проверку.
- **Инструменты** (`tools/`, Python, игра закрыта): `export_world.py` — чистая копия мира для раздачи (без истории версий, игроков, прогонов уровней; с `levelmod_places.json` — локациями из `data/levelmod/worlds/<мир>/places.json`; LevelMod подхватывает их при первом открытии мира: проверено клиентским gametest в чистой папке игры); `release.py` — сборка `dist/` (манифест, шесть модов, мир) и публикация релиза через API GitHub (`--upload`, токен из `GITHUB_TOKEN`, с подтверждением).
- `versions/`: версии мира («простой git», бывший `VcsServer` BuildMod). Снимок — все файлы мира, кроме самой истории, `session.lock`, `*.lock` и того, что другие моды объявили через `WorldVersions.skipTopLevel(имя)` (BuildMod: `buildmod_buildings`). Файлы по SHA-256 в `<мир>/managementmod_versions/objects/`, описание — `commits/<id>.json`, указатель — `head.json`. Откат (2026-11-11, по просьбе: «по такому же принципу, как откат после уровня»; собрано, **в игре не проверено**): если LevelMod подключил движок `WorldVersions.liveRollback` (`LiveRollback.begin`), мир возвращается к версии **без остановки**: сервер двигает указатель и отдаёт откат движку (`WorldReset.beginManual` в LevelMod: по одному чанку за тик с бюджетом времени, блоки и сущности, весь мир по чанкам версии), процент идёт всем игрокам над панелью, окно V показывает «Идёт откат мира…» и блокирует кнопки (`Versions.live`, `Versions.busy`); пока откат идёт, сохранять, откатывать и удалять версии нельзя (`rolling`). Движок живёт в LevelMod, потому что зависимость идёт LevelMod → SmesharikiMod; нужен уровень не идёт (иначе отказ, указатель возвращается). **Не возвращает:** чанки, созданные после версии (в ней их нет), состояние хранилищ BuildMod в памяти и `data/gameplaymod` (читаются при загрузке мира), смешариков, игроков и сущности `buildmod:*`; изменения во время отката могут не вернуться. Без LevelMod прежний путь: указатель, `pending.json`, остановка, на `SERVER_STOPPED` файлы заменяются версией (новых версий не создаёт). Папка прежнего имени `buildmod_vcs` переименовывается при первом открытии мира. **Только хост** (владелец мира; на выделенном сервере — операторы) и **только в творческом режиме** (в выживании окно закрыто, сервер отказывает). Клавиша V (`key.smesharikimod.versions`).
- **API для других модов:** `versions/WorldVersions` — `skipTopLevel(имя)`, `currentFiles(корень мира)` (путь → хеш текущей версии, `null` — версий нет), `read(корень, хеш)`. LevelMod читает версию только так; формат файлов истории знает один этот мод.
- `client/LanSettings`: на экране «Сетевая игра» (пауза) кнопка «Проверка аккаунтов: вкл/выкл» (`config/smesharikimod_lan.txt`, прежний `buildmod_lan.txt` переносится). При «выкл» и открытом для сети мире каждый тик клиента `server.setUsesAuthentication(false)` (как `online-mode=false`): **любой в сети может зайти под любым ником** — решение пользователя, «пока не важно»; побочное: хост по версиям определяется по нику.

## Состояние

- Перенос и переименование (2026-11-10): собрано; **в игре не проверено**: окно версий и откат на новом месте, миграция папки `buildmod_vcs`, кнопка в «Сетевой игре», передача файлов после переименования (имена пакетов теперь `smesharikimod:*`).
- **Версии хранят только состояние мира (2026-11-10, решение пользователя; собрано, в игре не проверено).** Раньше в снимок шло всё, кроме истории; теперь по списку разрешённого (`VcsServer.KEEP`, шаблоны путей от корня мира через `/`, `*` — любой сегмент): блоки и сущности всех измерений (`dimensions/*/*/region`, `entities`, `poi`) и `data/gameplaymod` (вселённые смешарики, маршруты брёвен — привязаны к сущностям); другие моды добавляют своё через `WorldVersions.keep(шаблон)` (BuildMod: платформы, стены, ковры, картины и их папка). **Не входят и откатом не трогаются:** `players`, `level.dat`, `data/minecraft`, `data/levelmod` (прогоны), `behaviormod` (кат-сцены), `buildmod_buildings`, `buildmod_slots.json`, `dimensions/*/*/data`. Старые версии содержат и это: при откате такие файлы из них пропускаются (`applyPending` фильтрует через `kept`). Первая новая версия просто перестанет содержать лишнее. `skipTopLevel` остаётся для исключений на верхнем уровне.
- **Устаревшие моды при установке с GitHub (2026-11-13, по просьбе; логика проверена `docs/level-sim` → `gitTest` (18 проверок), **в живой игре не проверено**).** Причина: у другого клиента (macOS) в `mods` лежали `smesharikiworld-1.0.0.jar` и `worldmod-1.0.0.jar` вместе — краш «Adding duplicate key 'buildmod:island'». Манифест релиза теперь может нести `"obsolete": ["smesharikiworld-1.0.0.jar", "installermod-1.0.0.jar"]` (`tools/release.py`, список `OBSOLETE`): `GitRelease.Plan.obsolete` — те из них, что реально лежат в `mods/` (небезопасное имя отвергает весь манифест); окно установки добавляет в предупреждение их список, `GitSession.disableObsolete` после установки переименовывает их в `*.smesharikimod-old` (не удаляет), отметка «нужен перезапуск» ставится; `GitUpdate` предлагает установку и тогда, когда ставить нечего, а устаревшее есть. Плюс `"breaks": {"smesharikiworld": "*"}` в `WorldMod/fabric.mod.json`: Fabric сам сообщает о конфликте вместо краша. **Действует только после нового релиза с этим кодом**: у клиентов на `v0.1.0` установщика без `obsolete` нет, им надо вручную удалить старый jar.

## Общий интерфейс окон (`com.smeshariki.ui`, бывший мод UiLib, влит 2026-11-13)

Код — `src/client/java/com/smeshariki/ui/`, подписи — `src/main/resources/assets/uilib/lang/` (ключи `gui.uilib.*`; пространство имён ресурсов осталось `uilib`, чтобы не переименовывать ключи). **Только клиентский код**, без сущностей, предметов, пакетов и записей реестров: сохранённых миров не касается, на выделенном сервере ничего не загружает. Прежний мод `uilib` (id, `uilib-1.0.0.jar`) удалён: рядом со влитым он давал бы дубли классов, поэтому его отключает установщик (`obsolete`), а у ручной установки старый jar надо удалить.

### Правила работы

- После правки API пересобрать все зависимые моды (порядок — `../CLAUDE.md`), иначе в игре `NoSuchMethodError`; в игре все шесть jar одной сборки.
- Сюда — только то, что нужно двум и более модам и не знает о логике ни одного. Окно, которое нужно одному моду, остаётся в этом моде. Менять сигнатуры осторожно: зависимых пять (GameplayMod, BuildMod, BehaviorMod, LevelMod и сам SmesharikiMod).

## Что здесь есть (`com.smeshariki.ui`)

- `UiScreen` — основа окна: мир идёт дальше (`pausesGame()` по умолчанию ложно; окно, которое раньше ставило игру на паузу, переопределяет его в `true`), `parent` и закрытие возвращают в окно, откуда открыли, `panelWidth/listWidth/centered`, `drawHeader`, `drawNote`, кнопки `addBack`, `addDelete` (✕ с подсказкой), `addMoveButtons` (↑ ↓ строки списка), **`isEditing()`** — идёт ли ввод в поле. Окно, которое перестраивается по новому списку от сервера, пишет в `tick`: `if (изменилось && !isEditing()) rebuildWidgets();` (иначе перестройка во время набора сбрасывает фокус и текст); если Enter в поле запускает действие, после него `setFocused(null)`, иначе отложенное обновление не применится.
- `ListScreen` (от `UiScreen`) — окно с одним списком из кнопок и полосой прокрутки `bar`: колесо, ползунок, клик по дорожке и перестройку делает сам. `init` строит строки так: `bar.layout(x + w + 3, TOP, visible * ROW - 2, size, visible)`, строки от `bar.scroll`; `rowsFit(top, reserve, row)` — сколько строк помещается. `onScrolled()` — что делать при сдвиге прокрутки (по умолчанию перестроить окно; `SelectScreen` обновляет только строки, поле поиска остаётся).
- `Scroller` — полоса прокрутки; прямое использование для окон с двумя списками или сеткой (`PlatformsScreen`, `MaterialsScreen` в BuildMod).
- `CardList` — список карточек слева (уровни, задачи, локации, группы): область, прокрутка в пикселях, фон (обычный, под курсором, выбранный), обрезка, выбор по клику (`rowAt`), содержимое рисует окно в замыкании `draw(...)`; у края списка тонкий индикатор прокрутки (только показывает положение, мышью не тянется).
- `SelectScreen<T>.open(parent, title, options, label, current, apply)` — выбор из списка с поиском (бывший LevelMod `SelectScreen`); `PromptScreen.open(title, hint, initial, accept)` — строка ввода (бывший BehaviorMod `PromptScreen`; есть перегрузка со `String`).
- `Ui` — палитра (`TEXT`, `HINT`, `MUTED`, `DIM`, `ACCENT`, `BAD`, `GOOD`, фон карточек), `BUTTON_H`, `ROW`, `firstLine`. **Золотой акцент один** (`ACCENT`, был четыре оттенка).
- Подписи `gui.uilib.*` (`back`, `close`, `ok`, `cancel`, `delete`, `up`, `down`, `search`, `empty`) в `lang/ru_ru.json`, `en_us.json`.

## Правила для окон модов

- Цвета — `Ui.*`, не числа. Цвета окон в стиле ванили (`CharacterGearScreen`, `SyncScreen`: зелёная полоса, жёлтое) остаются своими.
- Тексты окон — языковые ключи мода: `Component.translatable("gui.<мод>.<окно>.<имя>")` или `I18n.get("…")` там, где нужна строка. **Не писать `%d`, `%.1f` в значениях:** ванильный загрузчик языков (`Language`, шаблон `%(\d+\$)?[\d.]*[df]`) молча превращает их в `%s`, число выйдет без форматирования. Формат — в коде (`String.format("%.1f", x)`), в строку — `%s`; `%` как знак пишется `%%`. Строки, которые сравниваются (`message.contains("не ")` в `CutsceneManagerScreen` — разбор ответа сервера), не переводятся.
- Ключи в BuildMod и BehaviorMod созданы скриптом из русских литералов: имя — транслит первых слов (`gui.buildmod.walls.stenj`…), а не смысл; при правке текста менять значение в lang, ключ можно оставить.
