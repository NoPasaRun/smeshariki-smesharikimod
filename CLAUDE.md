# ManagementMod

Управление игрой и миром. Minecraft 26.2, Java 25, Fabric (Loom). Id мода и пространство имён — `managementmod`, пакет `com.managementmod`. Использует `uilib` (общий интерфейс окон, `../UiLib/CLAUDE.md`; в `fabric.mod.json` — `recommends`, а не `depends`: мод должен запускаться один, чтобы поставить остальные с GitHub): собирать UiLib первым. Бывший InstallerMod (переименован 2026-11-10, решение пользователя); в него перенесены версии мира и переключатель проверки аккаунтов из BuildMod. Карта проекта — `../CLAUDE.md`.

## Правила работы

- **После каждой правки:** собрать (`./gradlew jar --no-daemon -Dorg.gradle.jvmargs=-Xmx900m`) и положить `build/libs/managementmod-1.0.0.jar` (не `-sources`) в `~/.minecraft/mods/managementmod-1.0.0.jar` атомарно (`cp` во временный `.jar.tmp` и `mv -f`). Старый `installermod-*.jar` из mods убрать: иначе два мода с одним делом.
- Собирать **раньше** BuildMod и LevelMod: они компилируются против `../ManagementMod/build/libs/managementmod-1.0.0.jar`.
- Графического клиента у агента нет: UI и передачу файлов он проверить не может; сервер — `./gradlew runServer`.

## Что здесь

- `sync/`, `net/`, клиентские `SyncClient`, `SyncScreen`, `SyncSession` (бывший InstallerMod): сервер при входе игрока отдаёт манифест файлов из `mods/`, `resourcepacks/`, `shaderpacks/`, клиент спрашивает подтверждение и качает куски; имена файлов проверяются, пути нормализуются, SHA-256 сверяется. Раздаются только те моды, что загружены при старте (`onlyServeLoadedMods`). Режим **с подтверждением** — решение пользователя, автоматическую установку отвергли как небезопасную. Настройки — `config/managementmod.json` (прежний `installermod.json` переносится сам).
- **Установка с GitHub** (2026-11-12, по просьбе: «загрузка с гита, если это сам хост»; логика проверена на локальном сервере, `docs/level-sim` → `gitTest`; **в живой игре и с настоящим GitHub не проверено**). `sync/GitRelease` (без Minecraft): последний релиз репозитория `владелец/имя` (`gitRepo` в `config/managementmod.json`, `gitAutoCheck`, `gitApiBase`) содержит `manifest.json` (файлы: имя, `category` mod/resourcepack/shaderpack/world, размер, SHA-256, для мира `world`) и сами файлы; в план идёт то, чего нет или что отличается по сумме, мир — только если папки в `saves/` ещё нет. Ходить можно только по https на узлы GitHub (каждая переадресация проверяется), `http://localhost` — только если `gitApiBase` указывает туда (для проверок). `client/GitSession` (тот же интерфейс `SyncView` и тот же `SyncScreen`, что и раздача с хоста): загрузка в отдельном потоке, сверка суммы, заменяемый файл → `*.managementmod-old`, мир распаковывается во временную папку (защита от zip-slip и архива-бомбы) и ложится в `saves/`. `client/GitUpdate`: один раз за запуск на экране заголовка, только с подтверждением. Новая категория `SyncCategory.WORLD` (последняя в протоколе; сервер мир не раздаёт). Хост-раздача для гостя осталась как была. Репозиторий по умолчанию — `NoPasaRun/smeshariki-demo` (`SyncConfig.gitRepo`); пустое значение отключает проверку.
- **Инструменты** (`tools/`, Python, игра закрыта): `export_world.py` — чистая копия мира для раздачи (без истории версий, игроков, прогонов уровней; с `levelmod_places.json` — локациями из `data/levelmod/worlds/<мир>/places.json`; LevelMod подхватывает их при первом открытии мира: проверено клиентским gametest в чистой папке игры); `release.py` — сборка `dist/` (манифест, семь модов, fabric-api, мир) и публикация релиза через API GitHub (`--upload`, токен из `GITHUB_TOKEN`, с подтверждением).
- `versions/`: версии мира («простой git», бывший `VcsServer` BuildMod). Снимок — все файлы мира, кроме самой истории, `session.lock`, `*.lock` и того, что другие моды объявили через `WorldVersions.skipTopLevel(имя)` (BuildMod: `buildmod_buildings`). Файлы по SHA-256 в `<мир>/managementmod_versions/objects/`, описание — `commits/<id>.json`, указатель — `head.json`. Откат (2026-11-11, по просьбе: «по такому же принципу, как откат после уровня»; собрано, **в игре не проверено**): если LevelMod подключил движок `WorldVersions.liveRollback` (`LiveRollback.begin`), мир возвращается к версии **без остановки**: сервер двигает указатель и отдаёт откат движку (`WorldReset.beginManual` в LevelMod: по одному чанку за тик с бюджетом времени, блоки и сущности, весь мир по чанкам версии), процент идёт всем игрокам над панелью, окно V показывает «Идёт откат мира…» и блокирует кнопки (`Versions.live`, `Versions.busy`); пока откат идёт, сохранять, откатывать и удалять версии нельзя (`rolling`). Движок живёт в LevelMod, потому что зависимость идёт LevelMod → ManagementMod; нужен уровень не идёт (иначе отказ, указатель возвращается). **Не возвращает:** чанки, созданные после версии (в ней их нет), состояние хранилищ BuildMod в памяти и `data/gameplaymod` (читаются при загрузке мира), смешариков, игроков и сущности `buildmod:*`; изменения во время отката могут не вернуться. Без LevelMod прежний путь: указатель, `pending.json`, остановка, на `SERVER_STOPPED` файлы заменяются версией (новых версий не создаёт). Папка прежнего имени `buildmod_vcs` переименовывается при первом открытии мира. **Только хост** (владелец мира; на выделенном сервере — операторы) и **только в творческом режиме** (в выживании окно закрыто, сервер отказывает). Клавиша V (`key.managementmod.versions`).
- **API для других модов:** `versions/WorldVersions` — `skipTopLevel(имя)`, `currentFiles(корень мира)` (путь → хеш текущей версии, `null` — версий нет), `read(корень, хеш)`. LevelMod читает версию только так; формат файлов истории знает один этот мод.
- `client/LanSettings`: на экране «Сетевая игра» (пауза) кнопка «Проверка аккаунтов: вкл/выкл» (`config/managementmod_lan.txt`, прежний `buildmod_lan.txt` переносится). При «выкл» и открытом для сети мире каждый тик клиента `server.setUsesAuthentication(false)` (как `online-mode=false`): **любой в сети может зайти под любым ником** — решение пользователя, «пока не важно»; побочное: хост по версиям определяется по нику.

## Состояние

- Перенос и переименование (2026-11-10): собрано; **в игре не проверено**: окно версий и откат на новом месте, миграция папки `buildmod_vcs`, кнопка в «Сетевой игре», передача файлов после переименования (имена пакетов теперь `managementmod:*`).
- **Версии хранят только состояние мира (2026-11-10, решение пользователя; собрано, в игре не проверено).** Раньше в снимок шло всё, кроме истории; теперь по списку разрешённого (`VcsServer.KEEP`, шаблоны путей от корня мира через `/`, `*` — любой сегмент): блоки и сущности всех измерений (`dimensions/*/*/region`, `entities`, `poi`) и `data/gameplaymod` (вселённые смешарики, маршруты брёвен — привязаны к сущностям); другие моды добавляют своё через `WorldVersions.keep(шаблон)` (BuildMod: платформы, стены, ковры, картины и их папка). **Не входят и откатом не трогаются:** `players`, `level.dat`, `data/minecraft`, `data/levelmod` (прогоны), `behaviormod` (кат-сцены), `buildmod_buildings`, `buildmod_slots.json`, `dimensions/*/*/data`. Старые версии содержат и это: при откате такие файлы из них пропускаются (`applyPending` фильтрует через `kept`). Первая новая версия просто перестанет содержать лишнее. `skipTopLevel` остаётся для исключений на верхнем уровне.
